# Updream

把一个 Updream（updream.cn）账号接入 DeepSeek Harness。启用后，模型可以在对话里直接生成图片或视频、把结果写回 Updream 的画布、上传本机素材，输入框旁边还会显示账号剩余积分。

Updream 是哔哩哔哩的 AI 创作平台，接口以 API Key（`sk-` 开头）认证。本插件用这套 Key 调用它的官方 REST 接口，不模拟网页登录态，也不共享任何账号凭据。

## 能做什么

四组能力，**默认全部关闭**，在「设置 → Updream → 能力」里逐个打开。之所以默认关闭：这些都是会真实消耗 Updream 积分、由模型自己决定何时调用的能力，而宿主没有「调用前先问一句」的机制。

| 能力 | 打开后的工具 | 计费 |
| --- | --- | --- |
| 生图 | `updream_generate_image` | 按张。普通档位约 15 积分/张，随模型与档位浮动 |
| 生视频 | `updream_generate_video` | 按秒。一次调用远高于一张图 |
| 文本 | `updream_generate_text` | 按次 |
| 画布与素材 | `updream_canvas`、`updream_projects`、`updream_node_create`、`updream_node_update`、`updream_node_connect`、`updream_node_disconnect`、`updream_node_delete`、`updream_asset_upload`、`updream_task` | 免费 |
| 删项目 | `updream_project_delete` | 免费，但**不可恢复** |

除了「画布与素材」，其余三组只生成结果、不写画布。想让结果落到画布上，就在生图或生视频时传 `on_canvas: true`，插件会先建节点再生成。

## 关于"等到一半"

宿主在 600 秒处强制结束任何一次工具调用。插件给自己的等待留了 30 秒余量
（视频工具 570 秒），所以超时总是由插件先报，报错里带着 `task_id`。

看到这个错误**不要重新提交** —— 任务仍在 Updream 服务端继续跑，重新提交就是再扣一次积分。
用 `updream_task` 带着那个 `task_id` 接着查：

```
updream_task({ task_id: "…", kind: "video", wait: true, wait_seconds: 120 })
```

`wait: true` 会轮询到任务结束或时间用完；`wait_seconds` 上限 500 秒，同样是为了不撞上宿主的 600 秒线。

## 使用方法

1. 打开 Updream 网页，进「设置 → API 密钥」，创建一个 Key。它只在创建时显示一次。
2. 在 DSH 打开「设置 → Updream」，把 Key 粘进「添加账号」点保存。插件会先向 Updream 验证一次，再存进本机凭据库。
3. 在「账号」栏选一个默认项目。不选的话，每次调用都得显式传 `project_id`。
4. 到「模型」栏刷新目录、勾选要用的模型，再到「能力」栏打开需要的那几组。
5. 回到对话，直接说「帮我画一张……」。

## 多账号切换

Updream 没有「登录为某个用户」这回事——**一个 API Key 就是一个账号**，`sk-` 属于谁，请求就以谁的身份发出。所以这里的「切换账号」就是保存多个 Key、选择用哪一个。

- **添加多个**：在「添加账号」里依次粘不同的 Key，可以各起一个名字（留空则显示 Updream 上的用户名）。同一个 Key 添加两次会被拒绝。
- **切换**：账号列表里点某一行的「切换」。切换立刻生效，**下一个请求就用新账号的 Key**，不需要重启、不需要重开会话。
- **在输入框切换**：打开「积分读数」后，输入框那枚胶囊点开就是账号菜单，勾选当前使用的账号，不用进设置页。
- **各账号的积分独立**：列表里可以单独「刷新余额」，只读你点的那一个账号。胶囊读数始终跟随当前账号。
- **删除**：移除只删本机保存的这份 Key，不会影响 Updream 上的账号。**删掉正用着的那一个时，剩下的第一个账号会自动接手**，插件不会停在一个已删除的 Key 上。

账号之间的数据**互相看不见**：Updream 的项目、画布、素材都归属于 Key 所属的那个用户。切到另一个账号后，之前那个账号的项目 id 会报「Project not found」——这是 Updream 的隔离，不是插件的 bug。所以**换账号时记得也换默认项目**。

**会员档位不同会表现成两种结果**：Updream 的模型目录把每个模型需要的最低档位（`origin` / `pro`）与账号自己的档位一起下发。插件会**优先挑当前账号用得了的模型**；要是你显式指定了一个档位不够的模型，Updream 会回 `MODEL_LEVEL_INSUFFICIENT`，这时换一个低档位模型即可。

## 关于删除项目

`updream_project_delete` 单独一组开关，和画布工具分开，因为这两种删除的性质不同：

- **删节点是软删除**，进回收站，能在网页上找回。
- **删项目不是**。Updream 的后端有 `DELETE /projects/{id}`（官方 CLI 没封装），但项目层面没有回收站：`/projects/trash`、`/projects/recycle`、`/recycle` 这些路由都不存在，实测全部 404。删掉后画布上的节点、连线和素材一起消失。

所以这个工具要求调用时显式传 `confirm: true`。不传时它只做只读检查，返回该项目当前的节点数、节点类型汇总、以及是否含已生成的结果——先让用户看清楚要删的是什么，再决定。检查走的是画布接口，所以 id 写错会先报 `NOT_FOUND`，不会误删。

## 关于文本接口的限制

这一点值得单独说明，因为它和大多数人以为的「接一个模型」不一样。

Updream 的 `/ai/chat` 与 `/ai/generate-text/async` 都是**一次独立的问答**：请求体只接受一条 `message`（或 `prompt`），不返回流式内容，不接受 system prompt，`messages` / `history` / `chat_history` 这类字段会被服务端静默忽略，工具调用也不支持。实测确认：把三段历史塞进 `messages`，模型仍然回答「你没有告诉我你的名字」。

所以 `updream_generate_text` 的描述里明确写了「它看不到本次对话」。这个工具适合「用 Updream 的额度跑一段独立的写作、翻译或摘要」，不适合接着会话思路往下改。**本插件不注册 Updream 的对话模型到 DSH 模型选择器** —— 那样做会把每一次带上下文的对话都变成一次丢历史的请求。

## 积分读数

打开「积分读数」后，输入框工具栏会出现一枚 `Updream · 985` 胶囊。点它会刷新，并跳到本插件的设置页。刷新间隔在「账号」栏选，默认 5 分钟。它只在打开的浏览器标签里轮询，关掉页面就停。

## 数据去哪了

- **API Key** 存在 DSH 的凭据库里（`kind: 'api-key'`），不进插件配置、不进日志、不进页面。每个账号一条记录，另有一条只存账号 id 的「当前账号」指针——指针里没有 Key，所以删账号不会留下残余的密钥。
- 设置页的 HTTP 路由只接受 loopback 请求，页面拿到的是脱敏后的状态。
- 生成的图片/视频在 Updream 的 CDN 上，是临时地址。要保留就立刻下载。
- 画布节点的删除是软删除，可以在 Updream 网页上找回。

## 已知限制

- **无流式、无多轮、无工具调用**：见上文。这不是本插件没实现，是 Updream 的接口没有。
- **按秒/按张计费**：插件不做本地额度预估。实际扣费以 Updream 返回为准。
- **图生视频只收一张首帧**：Updream 的 `image` 字段是单张。
- **团队空间**：在「账号」栏填团队 ID，会作为 `X-Workspace: team:<id>` 发出去。
- **画布刷新**：插件写入画布后，已打开的 Updream 网页不会自动刷新，需要手动刷新才能看到新节点。
